# Context-first Harness 설계

## 결론

Harness의 기본 역할을 에이전트·스킬·오케스트레이터 생성에서 프로젝트 컨텍스트 정리로 축소한다. 기본 산출물은 `AGENTS.md`, `ROADMAP.md`, `context/`이며, `_workspace/`는 사용자 승인 후에만 만든다.

## 목표

- 새 프로젝트에 최소 컨텍스트 구조를 설치한다.
- 기존 프로젝트의 컨텍스트 구조를 보존하며 정리한다.
- 여러 대화가 병렬로 작업해도 공통 파일 수정 충돌을 최소화한다.
- 에이전트, 스킬, 오케스트레이터 생성은 기본 범위에서 제외하고 별도 요청으로만 다룬다.

## 기본 구조

```text
AGENTS.md
ROADMAP.md
context/
├── ABOUT-ME.md
├── BRAND-VOICE.md
├── WORKING-RULES.md
├── GLOSSARY.md
└── LESSONS.md

_workspace/                 # 사용자 승인 후 생성
├── audit/
├── human/
└── machine/
    └── tasks/
        └── YYYYMMDD-task-name.md
```

`BRIEF.md`와 `HANDOFF.md`는 만들지 않는다. 개별 작업의 목표와 대화 이력은 해당 대화가 관리하고, 작업 상태와 인계 정보는 작업별 task 파일이 담당한다.

## 파일 책임

### `AGENTS.md`

런타임이 자동으로 읽어야 하는 짧은 프로젝트 규칙만 둔다. 프로젝트 구조, 작업 규칙, 검증 기준, 공통 파일의 소유권을 포함한다. 상세 지식과 실행 기록은 넣지 않는다.

### `ROADMAP.md`

프로젝트 목표, 대기 중인 일, 진행 중인 일, 완료된 일의 통합 현황을 관리한다. 일반 작업 대화는 읽기만 하며, 사용자가 요청한 조정 작업만 수정한다.

### `context/`

대화를 넘어 반복 사용할 장기 지식만 둔다. 실제 변화가 있을 때만 갱신하며, 실행별 상태나 원문 덤프를 넣지 않는다.

### `_workspace/`

- `audit/`: 검사와 검증 근거
- `human/`: 사람이 검토할 최종 산출물
- `machine/`: AI 작업 간 교환 정보
- `machine/tasks/`: 병렬 대화별 상태 파일

각 작업 대화는 고유한 `YYYYMMDD-task-name.md`만 수정한다. task 파일에는 목표, 상태, 작업 범위, 결과 위치, 후속 작업을 기록한다.

## 생성 및 정리 흐름

1. 프로젝트의 기존 지침, 문서, 산출물 폴더를 읽는다.
2. 신규 설치인지 기존 구조 정리인지 판단한다.
3. 기존 파일과 사용자가 작성한 내용은 보존한다.
4. `AGENTS.md`, `ROADMAP.md`, `context/`의 생성·보완안을 만든다.
5. `_workspace/`가 없으면 생성 전에 사용자 승인을 한 번 받는다.
6. 기존 `outputs/`, `artifacts/` 등 산출물 체계가 있으면 그대로 존중하고 `_workspace/` 생성을 강요하지 않는다.
7. 생성 후 파일 책임, 링크, 중복, 보안 정보 포함 여부를 검사한다.

## 병렬 작업 규칙

- 일반 작업 대화는 `ROADMAP.md`와 공통 context 파일을 임의로 수정하지 않는다.
- 각 대화는 자기 task 파일과 자기 산출물만 수정한다.
- 통합 상태 변경은 별도 조정 작업에서 task 파일들을 읽은 뒤 `ROADMAP.md`에 반영한다.
- 같은 날짜와 이름의 task가 이미 있으면 짧은 식별자를 붙여 새 파일을 만든다.
- 소스 코드가 아닌 일상 작업에 워크트리를 요구하지 않는다.

## 실패 처리

- 기존 산출물 체계가 불명확하면 `_workspace/`를 만들지 않고 사용자에게 확인한다.
- 공통 파일이 병렬 수정 중이면 덮어쓰지 않고 충돌 사실과 대상 파일을 알린다.
- 확실하지 않은 사용자·도메인 정보는 추정해 채우지 않는다.
- 환경변수, API 키, 인증 정보 관련 작업은 사용자 승인 없이 수행하지 않는다.

## 검증

- 기본 실행이 에이전트, 스킬, 오케스트레이터를 만들지 않는지 확인한다.
- 신규 프로젝트와 기존 프로젝트 정리 흐름을 각각 점검한다.
- 기존 `outputs/`가 있는 프로젝트에서 `_workspace/`가 자동 생성되지 않는지 확인한다.
- 두 병렬 작업이 서로 다른 task 파일만 수정하는지 확인한다.
- 일반 작업이 `ROADMAP.md`를 수정하지 않는지 확인한다.
- 공통 파일에 실행별 산출물이나 보안 정보가 들어가지 않는지 확인한다.

## 제외 범위

- 자동 에이전트·역할 설계
- 자동 스킬 생성
- 오케스트레이터 생성
- 런타임별 팀 아키텍처 패턴
- 모든 세션 종료 시 공통 파일을 갱신하는 절차
- 일상 작업을 위한 워크트리 생성
