# Harness Principles

이 문서는 런타임과 무관한 하네스의 공통 원칙만 다룬다. 특정 파일 경로, 도구명, 모델명은 `references/runtimes/` 아래 런타임 어댑터에서 결정한다.

## 목적

하네스는 단일 프롬프트를 다음 산출물로 바꾸는 메타 스킬이다:

1. 프로젝트/도메인에 맞는 역할 분해
2. 역할별 작업 원칙과 입출력 계약
3. 역할이 사용할 절차적 지식
4. 오케스트레이션 흐름
5. 검증과 반복 개선 루프
6. 다음 세션이 이어받을 수 있는 프로젝트 컨텍스트

## 분리 원칙

| 층 | 질문 | 산출물 |
|---|---|---|
| Core | 무엇을 설계해야 하는가? | 역할, 책임, 데이터 흐름, 검증 기준 |
| Runtime | 어디에 어떤 형식으로 구현하는가? | instruction 파일, skill 경로, agent 경로, delegation 방식 |
| Context | 다음 세션이 무엇을 알아야 하는가? | BRIEF, HANDOFF, ROADMAP, context 파일 |

Core 문서에는 특정 런타임의 경로, pointer file, delegation 도구명을 넣지 않는다.

## 작업 방식

1. 사용자 요청에서 목표와 도메인을 파악한다.
2. 런타임을 감지하거나 사용자 지정 런타임을 우선한다.
3. 기존 하네스가 있으면 파일 목록과 포인터 문서를 감사한다.
4. 역할을 2~7개 범위로 나눈다. 작을수록 조율이 쉽고, 많을수록 전문성이 커진다.
5. 역할마다 입력, 출력, 실패 처리, 협업 대상을 정의한다.
6. 역할별 절차 지식은 스킬로 분리한다. 짧고 전용이면 역할 문서에 포함할 수 있다.
7. 오케스트레이터는 “누가, 언제, 어떤 산출물을 넘기는가”를 정의한다.
8. 검증은 구조 검증, 드라이런, 트리거 검증, 산출물 품질 검증으로 나눈다.

## 문서 감사 기준

기존 문서를 재편할 때 각 문단을 다음 중 하나로 분류한다:

| 분류 | 기준 | 처리 |
|---|---|---|
| `core` | 역할 분해, 데이터 흐름, 검증 등 런타임 무관 원칙 | `references/core/`로 이동하거나 요약 |
| `runtime-specific` | 특정 도구, 경로, 모델명, instruction 파일 | 해당 `references/runtimes/{runtime}.md`로 이동 |
| `context` | 세션 관리, 사용자/브랜드/규칙/용어 컨텍스트 | `references/context/`로 이동 |
| `example` | 특정 도메인 예시 | 런타임 무관 예시와 런타임별 예시로 분리 |
| `stale/remove` | 현재 런타임 구조와 충돌하거나 중복 | 삭제 또는 역사적 참고로 격리 |

단순 문자열 치환은 금지한다. 먼저 문단의 추상 개념을 뽑고, 그 뒤 런타임별 구현으로 나눈다.

## 산출물 품질 기준

- 새 세션에서 바로 이어서 실행할 수 있어야 한다.
- 역할 문서와 스킬 문서는 서로 중복하지 않는다.
- 런타임별 산출물은 해당 런타임이 실제로 읽거나 사용할 수 있는 형식이어야 한다.
- 중간 산출물은 `_workspace/`에 남겨 감사와 재실행이 가능해야 한다.
- 보안 정보, API 키, 인증 정보 생성/수집/변경 절차는 포함하지 않는다.
